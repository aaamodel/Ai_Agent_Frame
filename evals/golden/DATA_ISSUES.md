## 这份台账解决什么问题

D1（黄金集抄 `examples`）的教训不是"这次改干净了"，而是：**这类问题不会报错、不会变红、
只会在被追问时才暴露**。所以本台账做两件事：

1. 把**已修复**的污染类问题连同**判据**记下来（判据已固化成
   `evals/tools/check_golden_purity.py`，可随时复跑）；
2. 把**语料本身的矛盾**逐条列出来 —— 黄金集的期望答案不能建立在自相矛盾的语料上，
   但语料改动影响面大，**需要你拍板**，我不擅自动。

复跑判据：

```bash
python -m evals.tools.check_golden_purity            # 有 FAIL 返回 1
python -m evals.tools.check_golden_purity --json evals/_results/golden_purity.json
```

## 二、F 类：语料内部矛盾（**需你拍板**，本次未改动）

这些是 `app/rag_data` 与 `raw_data` **自己跟自己打架**的地方。它们不直接让黄金集虚高，
但会让"标准答案"没有唯一解 —— 一旦被追问"依据哪份文档"，答不出或答成另一份都是隐患。

**我的处理原则**：只在黄金集的 `note` 里标注冲突、并把问法改成"两家文档一致的部分"
（例如 R13 已刻意不问威胁等级），**不擅自改语料**。因为语料改动会牵动多处引用，
且台账里很可能是"虚构种子数据待替换"阶段。

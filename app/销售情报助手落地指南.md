# 销售情报助手落地指南

> ⚠️ **本文档已过时（2026-09-19）**：文中提到的 `local_excel_tool` / Excel 直读通道
> **已全部退役**。销售业务数据现存储于 SQLite 业务库（`data/sales.db`），取数走
> `sales_sql_query`（自然语言）/ `sales_sql_write`（受约束写入）；规则与口径分别去
> `rag_knowledge_search`（`sales_kb`）与取数引擎的内置口径。
> 保留本文仅为历史沿革参考，**不要按其中步骤执行**。


> 配套交付物：`skills/sales-intelligence-assistant/SKILL.md` + `raw_data/sales_intel/` 下 4 份语料文档与 3 个 Excel 数据文件。
> 本指南说明如何把这些资料接入你的 agent 框架并跑通端到端流程，以及上线前必须完成的真实数据替换。

## 1. 交付物清单与角色

| 文件 | 角色 | 接入方式 |
|------|------|----------|
| `skills/sales-intelligence-assistant/SKILL.md` | 技能定义（渐进式披露入口） | **零操作**：SkillManager 启动扫描自动发现 |
| `raw_data/sales_intel/销售方法论与商机资质判定手册.md` | 阶段定义/MEDDIC/评分模型 | 上传至 Milvus `sales_kb` 集合 |
| `raw_data/sales_intel/公司产品知识库.md` | 产品权威信息源（含标准条目结构） | 上传至 `sales_kb` |
| `raw_data/sales_intel/竞品情报与市场侦察手册.md` | 竞品框架/侦察检索式/可信度分级 | 上传至 `sales_kb` |
| `raw_data/sales_intel/销售分析指标词典与诊断手册.md` | 指标口径/漏斗诊断决策树 | 上传至 `sales_kb` |
| `raw_data/sales_intel/客户线索台账.xlsx` | 线索读写数据面（轻量 CRM） | `sales_sql_query` 直读 |
| `raw_data/sales_intel/产品与报价表.xlsx` | 报价/毛利/折扣权限 | `sales_sql_query` 直读 |
| `raw_data/sales_intel/销售业绩月度表.xlsx` | 业绩分析数据面 | `sales_sql_query` 直读 |

**已按框架真实契约做过验证**（非想当然）：
- SKILL.md frontmatter 通过 `core/skill/manager.py` 解析逻辑模拟验证（name=目录名、描述 228 字符<1024、`allowed-tools` 为空格分隔字符串——**注意 YAML 数组写法会被 `isinstance(raw_tools, str)` 检查静默丢弃，此坑已规避**）；
- 三个 Excel 的每个 sheet 均 ≤50 行（`sales_sql_query` 无 cell 参数 read 时只返回前 50 行矩阵预览，这是硬契约）；
- 工具名与 `init_tools.py` 注册名逐一核对：`rag_knowledge_search` / `sales_sql_query` / `web_search` / `file_read_tool` / `file_grep_tool`。

## 2. 接入步骤

### 步骤 1：语料入库（约 5 分钟）

四份 `.md` 文档经现有 `/documents/upload` 接口入库，**指定独立集合 `sales_kb`**，避免污染默认知识库：

```bash
for f in "销售方法论与商机资质判定手册" "公司产品知识库" "竞品情报与市场侦察手册" "销售分析指标词典与诊断手册"; do
  curl -s -X POST "http://localhost:8000/documents/upload" \
    -F "file=@raw_data/sales_intel/${f}.md;type=text/markdown" \
    -F "collection_name=sales_kb"
done
```

> 若上传接口对 `.md` 的 MIME 解析有问题，把扩展名改为 `.txt` 后重传即可（内容不变）。

### 步骤 2：验证技能发现

重启服务，启动日志应出现技能数量 +1（现有 6 个投资类 skill → 7 个）。确认日志：
`skill sales-intelligence-assistant 扫描成功`（或"高级技能树扫描完成(7个)"）。

### 步骤 3（可选，推荐）：Tier2 常驻模式

按《垂直领域化实现方案.md》第 3 节启用 `domain_profile`，把销售助手设为常驻领域：

```dotenv
DOMAIN_PROFILE_NAME=sales-intelligence-assistant
DOMAIN_SYSTEM_PROMPT=你是公司销售情报与销售分析助手，基于台账、业绩数据与知识库事实作答，严禁编造数据。
DOMAIN_KB_COLLECTION=sales_kb
DOMAIN_ALLOWED_TOOLS=rag_knowledge_search sales_sql_query web_search file_read_tool file_grep_tool
```

不配置则走 Tier1 渐进式披露：用户问到销售类问题时模型自动读取 SKILL.md 并按其规则执行。

### 步骤 4：端到端验证（三条链路各问一句）

| 验证目标 | 示例问题 | 预期行为（看 trace） |
|----------|----------|----------------------|
| 产品情报链路 | "智能客服平台专业版多少钱？和智齿比优势在哪？" | 先 `rag_knowledge_search(collection_names=["sales_kb"])`，竞品动态补 `web_search`，报价引用产品目录 |
| 线索管理链路 | "华澜智造这个线索现在什么情况？" | `sales_sql_query` 读台账定位行 → 汇报状态/评分/下一步 |
| 销售分析链路 | "最近三个月赢单率什么趋势，问题出在哪个阶段？" | 读业绩月度表 → 按指标词典口径计算 → 决策树定位瓶颈 → 输出标准报告结构 |

## 3. 数据替换指引（上线前必做）

生成的数据是**结构完整、内部自洽的种子数据**（虚构公司名、按产品线真实定价逻辑构造），用途是让链路开箱即跑。上线前替换：

| 数据面 | 替换方式 |
|--------|----------|
| 线索台账 | 按"字段字典" sheet 的口径逐列替换为真实线索；行数超 50 时**按区域/月份拆 sheet**（50 行预览契约），或升级到方案见第 5 节 |
| 产品与报价表 | 替换为真实产品线、定价、成本与折扣权限（`公司产品知识库.md` 同步改） |
| 业绩月度表 | 导出真实月度数据；若来自 CRM，直接按字段字典口径做导出映射 |
| 产品知识库文档 | 把示例条目换成真实产品；`[待确认]` 项补齐后才算完成 |

**数据一致性红线**：台账的"状态"枚举、行业枚举必须与字段字典一致；业绩表口径必须与《销售分析指标词典》一致，否则 agent 的计算结果会失真。

## 4. 生产化约束（当前框架的已知边界）

1. **Excel 写入是单格写**：SKILL.md 已内置"读→复述→确认→单格写"协议规避误写；台账定位为**单人维护场景**，多人并发写会互相覆盖——多人场景走第 5 节升级路径；
2. **接口无鉴权**：对外/多人使用前必须在网关层加 API Key/JWT（项目介绍文档 5.2 已列）；
3. **外部情报依赖 web_search**：豆包搜索主梯队 + Tavily 兜底已就绪，但需确认 API key 配额覆盖销售团队的调用频率；
4. **`sales_sql_query` 无沙箱**：走 `os.path` 直读，Excel 路径部署变更时同步改 SKILL.md 的数据资产地图；
5. **Milvus 集合隔离**：`sales_kb` 与其他业务集合隔离，检索时 agent 被 SKILL.md 约束为限定 `sales_kb`（rag 工具的 `collection_names` 参数会强制执行）。

## 5. 升级路径（数据量/并发增长后）

1. **真 CRM 化**：`feishu.py` 已内置飞书多维表格工具（`feishu_bitable_tool`），把台账迁移到多维表格即可获得多人协作、字段校验与权限控制，SKILL.md 工具清单替换即可；
2. **数据库化**：`init_tools.py` 中 `DatabaseQueryTool`/`DescribeTableTool`/`ListTablesTool` 已实现但被注释——取消注释并接上 Postgres 会话工厂，业绩数据迁入数据库后分析查询不再受 50 行限制；
3. **自动化情报**：框架暂无调度器；如需"每日自动侦察竞品动向"，外部 cron 定时调 `/chat/with_agent` 是当前最省改动的方案。

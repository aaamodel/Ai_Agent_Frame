================================================================================
  repo_map.txt - Agent编排层 问题改写 + 意图识别 + 模式决策 改动骨架
  （基于真实 app/ 目录运行代码校准版，已删除无关 WORKFLOW/legacy 内容）
================================================================================

【改动背景（真实代码现状）】
  当前调用链：
    /chat/with_agent (chat.py:L85)
      → 直接实例化 AgentOrchestrator
        → orchestrator.run(user_input, session_id, mode="react")   ← ⚠️ mode 写死 react！
          → if mode == "plan_execute": _run_plan_execute() else: _run_react()
            → _run_reflection() (可选)
  问题：
    1. 编排模式（react vs plan_execute）目前由调用方传默认值，**完全没有**根据用户
       问题的复杂度/意图做决策。
    2. Agent 入口处**没有**跑"问题改写 + 意图识别"流程。
    3. 根目录 query_intent/ 下的 LLM 改写 + 意图分类（MultiQuestionRewriteService/
       DefaultIntentClassifier）目前**完全未接入** Agent 编排层。
    4. app/core/intent/recognizer.py 是关键词规则版 IntentRecognizer，
       只在非 Agent 的 /chat 接口使用，/chat/with_agent 未使用。

【改动目标】
  在 /chat/with_agent → AgentOrchestrator.run 之间插入一个 Pipeline：
    用户原始问题
      → 问题改写（含子问题拆分+复杂度分析+工具建议）
      → 意图识别（KB/MCP/系统意图）
      → 编排模式决策（react vs plan_execute）
      → 产出 IntentContext(preferred_mode, allowed_tools, slots)
      → 喂给现有 AgentOrchestrator.run(... , mode=..., intent=IntentContext)

  目标是：不改 ReActAgent / PlannerAgent / ReflectionAgent 三大执行引擎内部实现，
  只在"入口决策层"补齐能力，对执行层零侵入。

```python
orchestration/mode_decider.py
【待补充-⑨】核心：基于 Agent 改写结果 + 意图聚合信息 + 规则 + LLM 兜底，
              决策走 "react" 还是 "plan_execute"。
              输出 ModeDecision（字面量和现有类型 100% 对齐）。
"""

from dataclasses import dataclass
from typing import Optional, Literal

from query_intent.intent_dto import (
    AgentRewriteResult, AgentIntents, ModeDecision, TaskComplexityAnalysis,
)
from query_intent.intent_data_base import AgentChatContext
from query_intent.intent_service import IntentLLMService
from query_intent.intent_prompt.prompt_template_loader import PromptTemplateLoader
from query_intent.intent_utils import rag_trace_node
from query_intent.rag_constant import (
    ORCHESTRATION_MODE_DECIDER_PROMPT_PATH,
    MODE_DECISION_STEP_THRESHOLD,
    MODE_DECISION_TOOL_THRESHOLD,
    MODE_DECISION_DEFAULT,
)

@dataclass
class ModeDecider:
    """
    决策优先级（越高越先命中，不再走后续判断）：
      1. 用户明确步骤提示 explicit_plan_hint → plan_execute
      2. 规则阈值命中（步骤数/工具数）→ 若 enable_llm_confirmation 则调 LLM 二次确认
      3. LLM 综合判断（改写结果 + 意图 + 可用工具）
      4. 兜底 → 默认 react（保守低延迟）
    """
    llm_service: Optional[IntentLLMService] = None
    prompt_template_loader: Optional[PromptTemplateLoader] = None
    step_threshold: int = MODE_DECISION_STEP_THRESHOLD
    tool_threshold: int = MODE_DECISION_TOOL_THRESHOLD
    default_mode: Literal["react", "plan_execute"] = MODE_DECISION_DEFAULT
    # 是否启用 LLM 二次确认（关闭则纯规则，延迟最低）
    enable_llm_confirmation: bool = True
    # LLM 置信度低于该值时，回落 default_mode
    llm_confidence_floor: float = 0.6

    @rag_trace_node(name="mode-decide", type="MODE_DECIDE")
    def decide(
        self,
        rewrite: AgentRewriteResult,
        intents: AgentIntents,
        agent_context: Optional[AgentChatContext] = None,
    ) -> ModeDecision:
        """【待补充-⑨ 核心方法】返回 ModeDecision（mode 字面量与下游完全对齐）"""
        # 骨架：
        #  1. explicit_plan_hint 命中 → mode=plan_execute (confidence=0.95)
        #  2. 规则判断 _rule_based_decide(rewrite.complexity) → 若命中：
        #     - 若 enable_llm_confirmation=False → 直接返回
        #     - 否则调 LLM 二次确认（防止误切）
        #  3. 若 _rule_based_decide 未命中 → 调 LLM 综合判断
        #  4. LLM 失败/置信度过低 → fallback default_mode
        ...

    def _rule_based_decide(
        self,
        complexity: Optional[TaskComplexityAnalysis],
    ) -> Optional[tuple[Literal["react", "plan_execute"], str]]:
        """【待补充-⑨】基于阈值的规则判断。返回 (mode, reason) 或 None。"""
        # 规则：
        #  - estimated_steps >= step_threshold → plan_execute
        #  - estimated_tool_calls >= tool_threshold → plan_execute
        #  - has_multi_step_dependency and estimated_steps >= 2 → plan_execute
        #  - estimated_steps == 1 and estimated_tool_calls <= 1 → react
        #  - 其他 → None（无法判定，交给 LLM）
        ...

    def _llm_decide(
        self,
        rewrite: AgentRewriteResult,
        intents: AgentIntents,
        agent_context: Optional[AgentChatContext],
    ) -> tuple[Literal["react", "plan_execute"], str, float, Optional[str], Optional[str]]:
        """
        【待补充-⑨】LLM 判定。
        返回：(mode, reason, confidence, initial_plan_hint or None, first_tool_hint or None)
        """
        # 加载 ORCHESTRATION_MODE_DECIDER_PROMPT_PATH
        # 填充 slots: rewritten_question, sub_questions, complexity字段,
        #            intent_summary(从 intents 生成), available_tools(从 agent_context)
        # 调 IntentChoiceTier.FAST tier LLM
        # 解析 JSON（字段：mode, confidence, reason, initial_plan_hint, first_tool_hint）
        ...
```

```python
      - QueryTermMappingService / QueryTermMappingCacheManager：
        目前在 query_intent/query_intent_controller/ 下未接入 DB，
        【待补充-⑬-4-A】若后续要启用术语映射，需要在这里注入 DB Session + Mapper；
        首版可直接传 None / 空实例，mapping_svc 直接走空实现。
      - intent_node_mapper / intent_tree：首版直接使用
        query_intent/intent/intent_tree.py 中的全局意图树。
    """

    # 1) Prompt 模板加载器（跨请求共用，建议挂到 app.state，见下方 ⑬-5 lifespan）
    prompt_loader: PromptTemplateLoader = getattr(
        request.app.state, "prompt_loader", None
    ) or PromptTemplateLoader()

    # 2) 术语映射服务（首版可空，保留接口方便后续接 DB 映射表）
    #    【待补充-⑬-4-A】占位：后续接入 mapper 时替换为真实实现
    cache_mgr = QueryTermMappingCacheManager()            # 首版空实现
    mapping_svc = QueryTermMappingService(                # 首版空实现
        mapping_mapper=None, cache_manager=cache_mgr,     # None → 映射走空
    )

    # 3) RAG 配置属性（Agent 改写专用）
    cfg = RAGConfigProperties(
        # 保持与 MultiQuestionRewriteService 原有默认值一致即可
        query_rewrite_enabled=True,
        # 其他字段按需补，不强制
    )

    # 4) 改写服务（Agent 专用子类）
    rewrite_svc = AgentMultiQuestionRewriteService(
        llm_service=llm_svc,
        rag_config_properties=cfg,
        query_term_mapping_service=mapping_svc,
        prompt_template_loader=prompt_loader,
    )

    # 5) 意图分类器 + Resolver + Agent 专用聚合器
    #    【疑问-B 待确认后调整】
    #      若选择 B-1（chat 实际支持 dict）：classify_targets 不改动；
    #      若选择 B-2（只支持 IntentChatRequest）：在这里构造 classifier 前
    #        先执行【待重写-⑦-1】统一请求格式。
    classifier = DefaultIntentClassifier(
        llm_service=llm_svc,
        intent_node_mapper=None,    # 【待补充-⑬-4-B】= 意图树 mapper 单例；
                                    # 若 intent_tree 已全局暴露则传 None 也 OK
        prompt_template_loader=prompt_loader,
    )
    resolver = IntentResolver(intent_classifier=classifier)
    aggregator = AgentIntentAggregator(base_classifier=classifier)

    # 6) 模式决策器
    decider = ModeDecider(
        llm_service=llm_svc,
        prompt_template_loader=prompt_loader,
    )

    # 7) 组装 → Pipeline
    return AgentQueryIntentPipeline(
        rewrite_service=rewrite_svc,
        intent_resolver=resolver,
        intent_aggregator=aggregator,
        mode_decider=decider,
    )
```

```
# 角色
你是 Agent 编排策略专家，负责选择最合适的执行模式。

# 两种执行模式说明

## react 模式（ReAct：Thought + Action + Observation 循环）
适用场景：
- 单步或 2 步以内可解决
- 不需要严格的步骤先后依赖
- 适合：简单知识库查询、单工具调用、常见问答、闲聊问候、轻量计算
- 特点：响应快，灵活

## plan_execute 模式（Plan-and-Execute：先拆解子任务，再逐步执行）
适用场景：
- 预估 3 步及以上
- 存在明确步骤依赖（必须先做 A 才能做 B）
- 需要调用 2 个或以上不同工具/知识源
- 用户明确要求"分步骤""先...再...然后..."
- 复杂任务：方案制定、数据汇总对比、多维度分析、报告生成
- 特点：稳定可靠，但延迟更高
```

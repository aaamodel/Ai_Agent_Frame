# 压测专用问题集（每行一条；# 开头为注释，不会被当作 query）
#
# 为什么压测不能直接用黄金集
# --------------------------
# 黄金集里的 tool_cases 有相当一部分会触发**真实外部依赖**：
#   - 「智齿科技最近有什么新动作？」→ web_search（真实联网，收费 + 限流）
#   - 「今天上海天气怎么样？」      → web_search（同上）
#   - 「这个月的销售总额是多少？」   → local_excel_read_tool（读本地 Excel）
#   - 「帮我在多维表格里加一条记录」 → feishu_bitable_tool（写外部系统！）
# 这些一旦进入压测，P95 里混的就是「外部 API 的延迟」，而不是你系统的开销；
# 更糟的是最后一条会**真的往多维表格里写数据**。
#
# 因此本文件只收**纯内部依赖**的问题：答案都在本地知识库里，
# 走 RAG 检索，不触发任何外部 API、不做任何写操作。
#
# 与黄金集的关系
# --------------
# 这里的问题**刻意与 eval 黄金集同分布**（多数直接取自 rag_cases），
# 好处是压测的 P95 与 eval 的 Recall@5 可对照：
# 如果哪天 P95 变好了但 Recall 掉了，一眼能看出来是「牺牲质量换速度」。
#
# 用法
# ----
#   BENCH_QUERIES=benchmark/queries_bench.txt locust -f benchmark/locustfile.py ...
#   （或 bash benchmark/run_bench.sh，脚本默认就会带上这个文件）

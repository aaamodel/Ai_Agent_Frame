## Why

一条真实 trace 里，两次重规划共占 **20,041 输入字符（全部输入的 53.5%）**，但它们要解决的其实是**步级**问题：t1 读了技能文档、摘要丢掉了其中的路径，于是重规划只能盲猜目录，连续两次扫 `/data` 均为空。

根因不是"模型不聪明"，而是**纠偏通道缺一个输入**：

1. **重规划的输入里没有"可用的替代方向"**，模型只能发明方向——它发明了 `/data`，一个已被同一份输入记录证否的路径。模型面对的是"我该往哪纠偏"这个开放式问题，而它缺的正是回答这个问题所需的信息基础。
2. **执行期完全封闭**：`SubTaskOutcomeSchema` 只允许收缩（跳过 / 提前收尾）。单个子任务取不到数据时只记账、不处理，必须等整轮跑完，才由重规划从头修订计划——用整轮的代价处理步级的问题。

本变更要解决的正是这一点：**让纠偏从"发明方向"降级为"在候选里选"**。

关键分工是：

- **系统侧**负责产出确定性的候选方向集（已提取的结构化事实减去已试路径、工具白名单减去已用工具），并把已证否的方向**结构性剔除**；
- **模型侧**只做一件事——从这个列表里选一项，或者选"不选"。它不需要构造工具名、参数或路径。

这个分工也修正了"仅失败态才纠偏"的原设想：本 trace 的典型失败恰恰是**取到了数据但数据不对**（返回销售记录，问题问行业优先级），这种情形在原触发条件下不会开放纠偏通道。

## What Changes

- **新增候选方向列表**：由代码在子任务调用前确定性组装，来源为两个差集——① 已提取的结构化事实（数据资产及其位置）减去本轮已尝试过的路径；② 当前工具白名单减去本轮已调用过的工具。候选必须与当前白名单求交，已证否的路径必须剔除，总长受上限约束。
- **子任务输出增加选择字段**：模型只输出所选候选项的标识或"不选"，MUST NOT 自行构造工具名 / 参数 / 路径；系统负责把标识翻译为具体动作并应用到计划。
- **候选列表只在需要时注入**：本步取数未取得有效数据，或上一步自评为未解决 / 部分解决。正常成功的步骤不注入。
- **增加确定性的证据缺口检测**（零 LLM 调用）：问题侧核心词在本步返回内容中的覆盖率低于阈值时置位，作为开放纠偏通道的补充触发条件；核心词取自系统已有的结构化文本，不新增模型调用、不引入向量化。
- **纠偏受配额约束**，只改 cursor 之后的计划项，且必须留痕。

**不改动**：重规划节点本身（`fix-agent-context-loss` 已将其收窄为最后手段）、工具实现、工具白名单算法。

## Capabilities

### New Capabilities

- `agent/step-correction`: 执行期的就地纠偏——候选方向列表的确定性生成与注入边界、模型只能选择不能发明、纠偏的配额与作用域、以及留痕。

### Modified Capabilities

（无。本变更只新增执行期的纠偏能力；`agent/plan-execute-control` 的既有需求均不变——收缩操作（跳过 / 提前收尾）的语义保持原样，本变更是在其之外新增"换源"这一档。）

## Impact

**受影响代码**

- `app/core/agent/graph/nodes/execute_node.py`：候选方向列表的组装与注入、证据缺口检测、纠偏指令的解析与应用、留痕。
- `app/query_intent/llm_schemas.py`：`SubTaskOutcomeSchema` 增加可选的选择字段。
- `app/core/agent/graph/state.py`：已试路径、纠偏配额与纠偏留痕的存放。

**依赖**

- 候选来源之一依赖"结构化事实的提取"（`fix-agent-context-loss` 的 `agent/skill-document-loading`）。**若该能力尚未实现，候选来源退化为"工具白名单 − 已用工具"这一项，本能力仍可用**——只是少了资产路径这一档。两者可并行开发，不阻塞。

**不受影响**

- 工具实现、工具参数与工具白名单算法；不新增工具。
- 重规划的触发条件与次数上限（`fix-agent-context-loss` 已定义）。
- 执行器的收缩协议（跳过 / 提前收尾）语义。

**风险**

- **关键词覆盖检测无分词依赖**，召回可能偏低（中文复述会导致字面不匹配）。缓解：该信号只用于"多注入约 300 字符的候选列表"，误触发的代价很低；不用于任何阻断性判断。
- **候选集与白名单求交后可能为空**——本 trace 的白名单是 6 个工具且**不含任何 Excel 工具**，而技能文档声明的数据资产全是 Excel。这意味着即使提取出了路径，模型也用不了。缓解：候选为空时 MUST 记录告警，用于事后分析"白名单过窄"；这本身是一个有价值的观测点。
- **放开纠偏会重新引入计划膨胀的风险**。缓解：配额闸门 + 只改 cursor 之后的计划项 + 每次纠偏留痕。
- 候选列表注入会增加每次需要纠偏的子任务的输入（约 300 字符）；因只在需要时注入，且换来的是整轮重规划（8,536 字符决策 + 11,505 字符重跑）的减少，净收益明确。

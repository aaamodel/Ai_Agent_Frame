# Design：执行期就地纠偏（从"发明方向"到"在候选里选"）

动机与范围见 `proposal.md`。本文件只记录实现所必需的现状、决策与取舍。

## Context

实现本变更所需的现状（**均已核实**）：

- **执行期只能收缩**。`SubTaskOutcomeSchema` 只有 `next_action`(continue/finish) 与 `skip_task_ids`；`agent/plan-execute-control` 的既有需求明确写着"MUST NOT 提供新增子任务或修改既有子任务内容的能力"。
- **控制指令与结论已在同一次调用产出**——这是本变更可以零额外调用的前提。
- **可用工具白名单在状态里**：键名是 **`state["active_tool_names"]`**（不是 `allowed_tool_list`——后者在代码中不存在）。由 `prepare_node._resolve_tool_names()` 写入，`plan_node` / `execute_node` / `replan_node` 都在用。即"工具白名单 − 已用工具"这一侧候选**现成可用**。
- **已用工具与已试资产可从执行记录推导**：`subtask_results` 每条含 `tool_name`、`action`、`status`、`observation`、`llm_output`、`solved`，以及 **`action_input`——它是本次工具调用的**真实入参 dict**（`execute_node` 记账写入，另用于 `tool_args_hint` 占位符替换）。这是算"已试过什么资产"的关键输入，无需新增记录结构。
- **上一步的自评已有**：`SubTaskOutcomeSchema.solved` = yes / partial / no，与结论同调用产出。
- **结构化事实（数据资产及其位置）目前尚未进状态**——它在 `fix-agent-context-loss` 的 `agent/skill-document-loading` 里。本变更**依赖但不必等待**它：缺这一档时候选退化为"工具白名单 − 已用工具"。
- **`raw_slots` 的真实构成**（`intent_classify._extract_simple_slots`）只有五个键：`top_kb_node` / `top_mcp_node` / `top_system_node`（节点元数据，含 `full_path`、`collection_name`）、`intent_hit_tool_names`、`intent_prefer_mode`。**不存在** `entities` / `metrics` / `time_refs` 这类结构化实体槽位。
- **没有自研关键词抽取器**；trace 里出现的 "keyword extractor" 来自 LightRAG，它是**一次 3,058 字符的 LLM 调用**，复用它会违反"零额外调用"。
- **没有分词依赖**（`requirements.txt` 无 jieba / 同类库）。
- **本 trace 的白名单是 6 个工具**（rag_knowledge_search / knowledge_graph_search / web_search / file_read_tool / file_list_tool / file_grep_tool），**不含任何 Excel 工具**；而技能文档「数据资产地图」声明的资产**全部是 Excel**。即：即使提取出了路径，当前白名单下也用不了。

## Goals / Non-Goals

**Goals**

- 给执行期一个**封闭**的候选方向集，让模型从"发明方向"降级为"在候选里选"。
- 候选由代码确定性算出，零额外模型调用。
- 覆盖"取到了数据但数据不对"这种原触发条件覆盖不到的失败。
- 与已收窄的重规划形成分工：步级问题就地消化，方向性错误才交给重规划。

**Non-Goals**

- 不改动重规划的触发条件与次数上限（属于 `fix-agent-context-loss`）。
- 不改工具实现、工具参数与白名单算法；不新增工具。
- 不为关键词抽取新增模型调用，不引入向量化检索（分词使用本地 jieba，无外部调用）。
- 不改动执行器的收缩协议（跳过 / 提前收尾）语义——本变更是在其之外新增"换源"这一档。
- **不提供常驻的"工具能力索引"**（每次子任务都注入全部工具清单）。已确认不需要：候选方向列表本身已带工具名与一句话用途，足以支撑"选哪个方向"；常驻索引只增加固定开销，且会让模型分不清"我现在该换方向"与"我只是要知道有哪些工具"。

## Decisions

### D1：候选方向列表全部由代码算；只保留两个来源，去掉第三个

模型**不参与**候选的生成，也看不到差集的计算过程，只看到结果。

保留两个来源：

1. **已提取的结构化事实 − 本轮已试路径**（依赖 `agent/skill-document-loading`；缺失时该档为空）；
2. **当前工具白名单 − 本轮已调用工具**（`state["active_tool_names"]` − `subtask_results` 里出现过的 `tool_name`）。

**备选（否决）**：再增加第三个来源"cursor 之后尚未执行、且 precondition 与当前状态不冲突的计划项"。否决理由：① 它要求给 `SubTask` 新增 `precondition` 字段并改动规划提示词，范围显著扩大；② 这些步骤本来就会被执行，把它们列为"候选方向"会混淆"换源"与"继续"——模型要选的是"换个地方拿数据"，不是"要不要做下一步"。

### D2：两个差集各自"什么减什么"，以及白名单求交

**差集①（工具侧）＝ 当前白名单 − 本轮已调用工具**

- 被减数：`state["active_tool_names"]`；
- 减数：`subtask_results` 里出现过的 `tool_name` 集合；
- 结果：本轮尚未调用过的工具，作为"换工具"方向的候选。

**差集②（资产侧）＝ 已提取的结构化事实 − 本轮已尝试过的资产**

- 被减数：结构化事实，每条含「名称 / 位置 / 消费该资产所需的工具」；
- 减数：**用已提取资产的位置去反查 `action_input`**——把每条 `action_input` 的所有值拼成文本，若某资产的位置（或其文件名）出现在其中，即判定该资产本轮已被尝试过；
- 结果：本轮尚未尝试过的资产，作为"换数据源"方向的候选。

**为什么用"反查"而不是"抽取路径"**：各工具的路径参数名互不相同（`file_path` / `path` / `dir` …），猜参数名既脆弱又需要维护清单；反查不需要知道参数名，也不需要判断"什么算路径"——判定条件只是"这个资产的位置或文件名是否出现在本次调用的真实入参里"。匹配时对分隔符与大小写做归一化，并**同时匹配完整位置与文件名**（后者能覆盖"模型自己拼了目录但文件名写对"的情形）。

**为什么"已尝试过"就不进候选（不论成败）**：已成功 → 数据已拿到，无需再取；已失败/为空 → 已证否，必须排除。这正是"防止在同一方向重复试探"的结构性保证，与 D3 同源。

**白名单求交（本 trace 上最致命的一条）**：白名单没有能消费该资产的工具时，该资产**不能进候选**——否则模型选中一个它执行不了的方向，等于又制造一次失败。

本 trace 的白名单是 6 个工具（`rag_knowledge_search` / `knowledge_graph_search` / `web_search` / `file_read_tool` / `file_list_tool` / `file_grep_tool`），**不含任何 Excel 工具**，而技能文档声明的资产全部是 Excel——求交后资产侧候选会**直接为空**。

候选集求交后为空时 MUST 记录告警（含被排除的资产名称与原因）。这同时是一个高价值观测点：它会直接暴露"白名单过窄"这个独立问题。

### D3：已证否路径的剔除靠记录推导，不靠模型自觉

"已尝试且未取得有效数据"的判定来自 `subtask_results` 的 `status` 与 `action_input`，是**确定性**的。被判为无效的路径结构性排除出候选集——这正是"矛盾拦截"在执行期的对应物：**让错误方向根本不出现在选项里**，而不是等模型选中后再拦截。

### D4：模型只输出标识；系统负责翻译

模型输出所选候选项的标识（或"不选"），MUST NOT 自行构造工具名 / 参数 / 路径。系统按前缀把标识翻译为具体动作：

- `asset:<名称>` → 读取该资产（工具取结构化事实中记录的工具，路径逐字使用事实中的路径）；
- `tool:<工具名>` → 调用该工具。

翻译结果 MUST 过一次白名单校验。标识不在本次注入的列表里、或解析失败时，忽略该指令并按既有口径降级为"继续执行下一个子任务"，**本步结论不得被丢弃**。

**备选（否决）**：让模型输出完整的 `replace_next_with`（含工具名与参数）。否决理由：本 trace 已证明自由生成的纠偏方向会与同一份输入中的确定性记录矛盾，且没有机制能事前拦截；改成"从候选里选"之后，矛盾在构造阶段就被结构性排除。

### D5：注入时机 = 本步取数失败，或上一步自评为未解决

两个条件任一成立即注入候选列表。正常成功且上一步自评为已解决的步骤**不注入**。

**为什么不用"每步常驻"**：常驻会让模型分不清"我现在应该换方向"和"我只是需要知道有哪些工具"；且候选集依赖执行期状态，每步重算没有必要，也浪费固定的 ~300 字符。

**备选（否决）**：常驻注入。否决理由同上。

### D6：证据缺口检测 = 比对"问题侧核心词"与"本步返回内容"，用字面出现率

**比对的两个数据集**：

- **数据集 A（问题侧核心词）**——从系统**已有的结构化文本**抽取，按优先级取：① 本轮目标 `agent_goal`；② 子问题 `slots["per_sub_questions"]`；③ 意图树命中路径 `top_*_node.full_path`；④ 已提取的结构化事实。均缺失时回退到改写后的问题 `user_input`。
  抽取方式：**jieba 分词 + 停用词过滤**（已确认可引入该依赖，开销可忽略）。
- **数据集 B（本步返回内容）**——本步工具调用返回的原始文本 `observation`（上游已截到 8000 字符）。

**判据**：`coverage = |{w ∈ A : w 出现在 B 中}| / |A|`，低于阈值即置位。阈值做成配置项（初始 0.3，宁可多触发以收集数据；稳定后按 trace 统计上调）。

**两条必须的不置位条件**：A 为空 → 不置位；B 为空（纯推理步骤、或工具未返回文本）→ 不置位。宁可漏触发，不得误伤正常步骤。

**只比本步，MUST NOT 掺入历史结论**：历史结论的高覆盖率会把"本步返回跑题"掩盖掉。

**为什么是字面出现而不是语义相似**：本场景是**离散的字符串覆盖问题**——"行业""优先级"在销售记录里出现 0 次。向量化会把"行业"与"领域"拉近，反而引入噪声且不可解释。

**备选（否决）**：向量化语义匹配——引入噪声、不可解释、需额外 embedding 调用。
**备选（否决）**：复用 LightRAG 的关键词抽取器——它是**一次 3,058 字符的 LLM 调用**，违反"零额外调用"。
**备选（否决）**：字符 n-gram 免依赖方案——本方案的初版设计。分词精度足以支撑本场景且已确认可引入 jieba；n-gram 会产生大量无意义片段，稀释覆盖率。

### D7：纠偏的闸门与留痕

- **配额闸门**：单轮纠偏次数不超过剩余调用预算的一半，耗尽即关闭。
- **作用域闸门**：只改 cursor 之后的计划项；cursor 不变，已跳过记录与提前收尾标记不清空。
- **留痕**：每次纠偏记录触发条件、选中标识、目标动作、剩余配额；候选为空时记录被白名单排除的资产与原因。

**为什么闸门是必需组成部分**：执行期原本"只能收缩"正是为了防止计划无界膨胀。放开换源就必须补上约束，否则等于用一个更大的问题换一个小的问题。

### D8：与重规划的分工

| 场景 | 谁处理 |
|---|---|
| 计划方向对，某步没拿到想要的数据（含"拿到了但不对"） | **本变更**：执行期就地换源 |
| 计划方向本身错了（全部结论跑题） | 重规划（`fix-agent-context-loss` 已收窄为至多一次） |

本变更**不触碰**重规划的任何逻辑。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 字符 n-gram 召回偏低（中文复述导致字面不匹配） | 该信号只用于"多注入 ~300 字符的候选列表"，误触发代价低；不用于任何阻断性判断；核心词为空时不置位 |
| 候选集与白名单求交后为空（本 trace 即是：白名单无 Excel 工具） | MUST 记录告警；这本身就是"白名单过窄"的观测点。功能上退化为按既有流程继续，不中断 |
| 放开换源后计划无界膨胀 | D7 的配额闸门 + 作用域闸门 + 每次留痕 |
| 模型选中了候选但仍取不到数据 | 该次尝试进入"已试路径"，下轮候选自动剔除，不会在同一方向重复试探 |
| 依赖 `agent/skill-document-loading` 而它尚未实现 | 该档候选为空，能力退化为"工具白名单 − 已用工具"，链路仍可用；两者可并行开发 |
| 候选列表注入增加固定开销 | 仅按需注入，且换来的是整轮重规划（8,536 决策 + 11,505 重跑）的减少，净收益明确 |

## Migration Plan

无数据迁移。

- **部署**：`SubTaskOutcomeSchema` 的新增字段为可选，旧调用方零感知；候选与证据缺口检测均可通过配置开关关闭（回退到"不注入、不纠偏"）。
- **回滚**：`git revert` 本变更提交即可；新增状态键在旧代码中不被读取。
- **旧 checkpoint**：不含新键，读取侧按空处理，不影响恢复。

## Open Questions

- **候选标识的粒度是否够用？** 当前用 `asset:<名称>` / `tool:<工具名>` 前缀，系统翻译时不接受模型提供的参数。若将来需要"带参数的候选"（例如同一个资产用不同的查询条件），需要扩展标识格式与翻译规则。
- **纠偏配额的具体默认值**建议先取"剩余调用预算的一半"，上线后按 trace 调整。

- **`agent/plan-execute-control` 的 Purpose 与"MUST NOT 提供新增或修改子任务"这条需求是否需要在后续单独修订？** 本变更新增的"换源"是**新增一档能力**，不是修改既有需求——既有需求约束的是"模型不能凭空加步骤"，本变更下模型只能从系统给的候选里选，不违反该约束。但如果希望主 spec 的表述更完整（明确"收缩之外还有受约束的换源"），可另开变更处理。

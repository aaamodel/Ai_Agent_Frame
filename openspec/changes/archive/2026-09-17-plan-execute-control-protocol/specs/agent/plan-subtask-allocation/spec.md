## Purpose

保证意图层拆分出的每个子问题都拥有独立对应的执行子任务，避免为了节省调用次数而合并子问题，导致某些子问题最终无答案且链路无法察觉。

## ADDED Requirements

### Requirement: 每个子问题必须有独立对应的子任务

当意图层判定用户问题需要拆分并产出 N 个子问题（N > 1）时，规划结果 MUST 至少为每个子问题派发一个明确对应该子问题的子任务（可接受工具型或推理型子任务）。

#### Scenario: 两个子问题各获得一个子任务

- **WHEN** 用户问题被拆分为「私有化部署一般多久上线」与「实施费怎么收」两个子问题
- **THEN** 规划结果 MUST 至少包含两个子任务，且分别明确对应上述两个子问题

#### Scenario: 未拆分子问题时按任务需要规划

- **WHEN** 意图层判定无需拆分（子问题数 <= 1）
- **THEN** 规划 MUST 按任务本身的步骤需要决定子任务数量，不受子问题数量约束

### Requirement: 禁止以“可由同一次工具调用覆盖”为由合并子问题

系统 MUST NOT 将「多个子问题可由同一次工具调用覆盖」作为合并子任务的依据。即使多个子问题预期命中同一份数据源，MUST 仍为它们各自派发子任务。

#### Scenario: 同源子问题仍分别派发

- **WHEN** 两个子问题的答案预期出现在同一份知识库文档的同一段落中
- **THEN** 规划 MUST 仍为两个子问题各派发一个子任务，MUST NOT 合并为单次检索

### Requirement: 覆盖缺失必须被检出并处理

系统 MUST 在计划解析阶段校验每个子问题是否被至少一个子任务覆盖。校验未通过时 MUST 先触发一次重新规划；重新规划后仍未覆盖时，MUST 记录明确告警并继续执行（不得无限重试，也不得静默丢弃）。

#### Scenario: 计划未覆盖某子问题时触发重规划

- **WHEN** 生成的计划中某个子问题没有任何子任务对应
- **THEN** 系统 MUST 触发一次重新规划

#### Scenario: 重规划后仍缺失则告警继续

- **WHEN** 重新规划后的计划仍未覆盖全部子问题
- **THEN** 系统 MUST 记录一条含缺失子问题标识的告警，并使用当前计划继续执行

# Evidence Board Specification

## Purpose

在一次请求的多轮工具调用中，把逐字累积的原始工具观测替换为按问题相关性确定性筛选、跨轮去重、预算受控的证据板，并支持模型按编号回取原文，从而在不丢失关键证据的前提下消除上下文随轮次线性膨胀。

## ADDED Requirements

### Requirement: 工具观测必须归一化为带稳定编号的证据单元

系统 MUST 在每次工具观测产生后，将其确定性切分为若干证据单元。每个单元 MUST 携带：请求内稳定且可被模型引用的编号、来源工具、产生轮次、来源标识（文档名/文件路径等，可得时）、块原文与可用于回取的坐标。

切分 MUST NOT 改写、摘要或生成原文内容；同一条证据原文在发送给模型的消息中 MUST NOT 重复出现。系统 MUST 区分内容单元与错误/状态单元：以错误返回或无结果状态产生的单元 MUST 被标记为错误/状态单元。

零 LLM 调用：归一化过程 MUST NOT 发起任何模型调用。

#### Scenario: RAG 多片段观测被拆成独立单元

- **WHEN** 一次知识库检索返回 5 个带来源文献名的内容片段
- **THEN** 系统 MUST 产出 5 个各自带唯一编号、来源标识与原文的内容单元，且片段文本未被改写

#### Scenario: 短观测不切分

- **WHEN** 工具返回不超过短观测阈值的文本
- **THEN** 系统 MUST 将其整体作为一个单元，MUST NOT 进一步切分

#### Scenario: 工具错误被标记为错误单元

- **WHEN** 工具返回错误文本或空结果状态
- **THEN** 系统 MUST 产出标记为错误/状态的单元，MUST NOT 将其当作普通内容参与相关性选择

### Requirement: 证据上板必须基于与问题的相关性并跨轮去重

系统 MUST 依据"本轮工具查询"与"用户原始问题"的词项，对全部内容单元进行确定性相关性评分；评分 MUST 同时纳入本轮查询词与原始问题词，以防单轮查询过窄导致相关证据落选。

只有评分达到相关性阈值的内容单元才有资格进入证据板。系统 MUST 对跨轮内容单元做重复检测；被判为重复的单元 MUST NOT 重复上板，系统 MUST 保留其中相关性更高者，分数相同时保留更新的单元，并 MUST 保留被合并单元的来源（多来源互证信息不得丢失）。

#### Scenario: 与问题相关的单元优先上板

- **WHEN** 同一轮观测中同时存在命中问题核心词的单元与无关单元，且上板名额不足
- **THEN** 系统 MUST 选择评分更高的相关单元，无关单元 MUST NOT 挤占名额

#### Scenario: 本轮查询过窄时原始问题词可救回证据

- **WHEN** 本轮工具查询未包含某条证据的词项，但该证据命中用户原始问题的词项
- **THEN** 该证据 MUST 仍能达到上板阈值，MUST NOT 仅因本轮查询未命中而落选

#### Scenario: 跨轮重复内容只保留一份且不丢来源

- **WHEN** 第 2 轮检索返回与第 1 轮某单元语义重复、但来源文档不同的内容
- **THEN** 发送视图中 MUST NOT 出现两份重复全文，保留单元 MUST 同时携带两个来源标识

### Requirement: 证据板容量必须按轮次收紧

证据板每轮 MUST 从全部已收集单元重新选择，而非仅追加。系统 MUST 对每轮施加上板条数与字符数双重预算，预算随轮次增长但 MUST 存在封顶：首轮字符预算为 1200，每轮增加 400，封顶 2400；上板条数首轮至多 5 条，每轮增加 1 条，封顶 10 条。

同主题单元 MUST 被多样性选择打散，避免多条名额陈述同一信息。超出单条字符预算的单元 MUST 在句子边界截断并明确标注其为截断内容。

#### Scenario: 后续轮次证据板不无限膨胀

- **WHEN** 已进入第 4 轮或更多轮工具调用
- **THEN** 证据板总字符数 MUST NOT 超过 2400，上板条数 MUST NOT 超过 10

#### Scenario: 同主题结果被打散

- **WHEN** 候选中多条单元陈述同一信息、仅有表述差异
- **THEN** 系统 MUST NOT 让同主题单元占满上板名额，MUST 为不同主题保留名额

### Requirement: 短观测必须豁免评分并限期原文保留

当整条工具观测为非错误/状态内容且长度不超过 300 字符时，系统 MUST 将其整体作为一个标记为豁免的证据单元：MUST NOT 进一步切分、MUST NOT 进行相关性评分，且该单元 MUST NOT 占用证据板的条数与字符预算。

豁免单元 MUST 参与逐字精确去重；被判为与既有单元逐字重复的豁免单元 MUST NOT 占用豁免原文保留名额，仅以一行重复指针呈现。

ReAct 路径（函数调用协议与文本协议）中，豁免单元自其产生轮次起 3 个轮次内 MUST 以原文呈现；超过 3 个轮次后 MUST 收敛为一行桩，桩 MUST 至少包含：证据编号、来源工具名、原始字符数与一行首句预览，且该单元 MUST 仍可通过证据编号回取。plan_execute 路径中，当前子任务的豁免单元 MUST 原文呈现。

#### Scenario: 短目录观测三轮内原文呈现其后桩化

- **WHEN** file_list 工具返回一条 120 字符的目录列表，其后又进行了 3 轮以上工具调用
- **THEN** 产生后的 3 个轮次视图中该观测 MUST 原文可见且不占证据板预算；第 4 个轮次起它 MUST 以含编号、工具名、字符数与首句预览的一行桩呈现，并可按编号回取

#### Scenario: 重复短观测不得占用豁免名额

- **WHEN** 同一目录列表在相邻轮次被逐字重复返回两次
- **THEN** 后一份 MUST 被精确判重为一行重复指针，MUST NOT 作为第二条豁免原文占用保留名额

### Requirement: 错误与被省略证据必须保持可感知

系统 MUST 在每轮发送视图中始终包含最近一轮全部错误/状态单元的至少一行呈现，错误信息 MUST NOT 因压缩或低相关性而消失。

未上板的非错误单元 MUST 以一行索引呈现，至少包含：证据编号、来源标识与低相关性提示。每轮视图 MUST 给出本轮证据总量、上板量、低相关量与重复量的计数。

#### Scenario: 工具失败在后续轮次仍可见

- **WHEN** 第 1 轮某工具调用失败，第 3 轮组装发送视图
- **THEN** 该失败 MUST 仍以至少一行出现在发送视图中，MUST NOT 被完全省略

#### Scenario: 低分证据留下可引用的索引

- **WHEN** 某单元评分低于阈值未上板
- **THEN** 发送视图 MUST 保留包含其编号与来源的一行索引，使该证据可被模型发现并回取

### Requirement: LLM 发送视图必须呈现证据板而非累积原始观测

系统在 ReAct（函数调用协议与文本协议）每轮发给模型的工具观测视图 MUST 由证据板、豁免期内短观测原文、超期豁免桩、重复指针、低分索引与错误行构成；除豁免期（3 个轮次）内的短观测外，MUST NOT 再逐字重放其他历史观测全文。视图 MUST 保持消息协议合法性（函数调用协议下工具消息与工具调用配对、内容非空），且同一条证据全文 MUST NOT 出现多次。

系统 MUST NOT 改动证据相关消息之前的稳定前缀（系统提示与首轮用户消息），证据预算与回取提示 MUST 出现在消息序列末端。

plan_execute 模式下，子任务提炼所看到的本步工具数据 MUST 按同样的相关性规则选择呈现，MUST NOT 再使用不看内容的头部固定长度截断；观测不超过 300 字符时 MUST 原样呈现。被省略单元 MUST 以索引呈现并允许模型通过独立的证据请求字段索取其全文（见"计划子任务可延迟一步回取本步被省略证据"）。

#### Scenario: 多轮 RAG 后发送视图显著缩短且关键证据仍在

- **WHEN** 连续 3 轮知识库检索、每轮返回 5 个长片段后组装下一轮发送视图
- **THEN** 视图 MUST NOT 重放 15 个片段的全文，且答案所需的关键证据 MUST 全部在板

#### Scenario: 稳定前缀字节不变

- **WHEN** 引入证据板后组装任一轮发送视图
- **THEN** 系统提示与首轮用户消息（含技能全文）的内容 MUST 与引入前一致

#### Scenario: 计划子任务的长观测改为按相关性呈现

- **WHEN** plan_execute 某子任务工具返回超过短阈值的长观测，关键信息位于观测尾部
- **THEN** 子任务提炼视图 MUST 能呈现位于尾部的相关内容，MUST NOT 因头部固定截断而将其丢弃

### Requirement: 模型可按编号回取被省略的证据原文

ReAct 路径 MUST 向模型提供按证据编号回取原文的能力，支持仅取回该单元或连同其前后相邻单元。回取 MUST 只读取本请求已保存的观测，MUST NOT 因此重新调用任何外部工具或产生外部额度消耗。

模型显式回取过的单元在下一轮视图中 MUST 被保留：它 MUST 享有选择优先级且至少保留到下一轮，同时 MUST NOT 因重复回取同一编号而重复占用上板预算。编号不存在或相邻窗口越界时，系统 MUST 返回与普通工具错误同形的确定性错误文本（包含可用编号提示），MUST NOT 抛出异常中断循环。

ReAct 路径的即时回取 MUST NOT 出现在 plan_execute 子任务提炼调用中（该次调用不携带工具通道）；plan 路径的回取需求 MUST 由独立的延迟一步通道承载（见下一需求）。

#### Scenario: 回取被省略单元不触发外部调用

- **WHEN** 模型请求取回某低相关索引单元的原文
- **THEN** 系统 MUST 从本请求已保存观测返回原文，且外部工具 MUST 被零次调用

#### Scenario: 回取相邻窗口

- **WHEN** 模型请求取回某单元及前后各 2 条相邻单元
- **THEN** 系统 MUST 返回该单元与其同一次观测内相邻单元的原文，MUST NOT 重新检索

#### Scenario: 非法编号得到确定性错误

- **WHEN** 模型请求一个不存在的证据编号
- **THEN** 系统 MUST 返回列出可用编号的错误文本并继续循环，MUST NOT 中断执行

### Requirement: 计划子任务可延迟一步回取本步被省略证据

plan_execute 子任务提炼的输出协议 MUST 包含一个独立的可选字段（`requested_evidence_uids`），供模型声明需要查看全文的、本步被省略证据单元的编号；该字段 MUST 与选择候选资产/替代工具方向的字段（`selected_alternative_id`）语义分离、互不影响，且系统 MUST 在提炼提示词中以简短规则说明两者各自用途。

系统 MUST 仅受理同时满足以下条件的编号：属于当前子任务轮次、为内容/表格类单元、且确实在本步被省略；不合法或越权的编号 MUST 被拒绝并留痕，MUST NOT 中断提炼结论的正常应用，单次请求受理数量 MUST NOT 超过 3 条。

对受理的编号，系统 MUST 在当前子任务之后插入一个内部恢复步：该步 MUST NOT 出现在工具注册表中、MUST NOT 调用任何外部工具，MUST 仅从本请求已保存的观测中取出对应证据原文并作为该步观测，随后正常进行一次提炼。每个子任务 MUST 至多触发一次恢复；恢复步的提炼输出中的证据请求 MUST 被忽略。恢复步 MUST 计入既有的步级纠偏配额与留痕，并受禁止链式纠偏的同一约束。

#### Scenario: 模型索取被省略证据后内部步零外部调用回填

- **WHEN** 某子任务提炼输出在 `requested_evidence_uids` 中填写了本步两个被省略单元的编号
- **THEN** 系统 MUST 在该子任务后插入一个内部恢复步，恢复步观测 MUST 为这两个单元的已保存原文，外部工具 MUST 被零次调用，随后 MUST 再进行一次提炼

#### Scenario: 证据请求与候选方向选择互不干扰

- **WHEN** 模型在同一次提炼中同时填写了 `selected_alternative_id` 与 `requested_evidence_uids`
- **THEN** 系统 MUST 将二者分别解释为"换数据源/工具方向"与"索取本步证据全文"，MUST NOT 因其中一个字段存在而忽略另一个

#### Scenario: 越步或伪造编号被拒绝且不中断

- **WHEN** 模型填写了属于其他子任务轮次或根本不存在的证据编号
- **THEN** 系统 MUST NOT 插入恢复步，MUST 正常应用本次提炼结论，并在留痕中记录被拒绝的编号

#### Scenario: 每个子任务最多恢复一次

- **WHEN** 内部恢复步的提炼输出再次携带证据请求编号
- **THEN** 系统 MUST 忽略这些编号，MUST NOT 再插入第二个恢复步

### Requirement: 证据管道不得阻断执行主链路

证据归一化、评分、去重、选择、渲染或回取中的任何环节发生异常时，系统 MUST 自动降级为既有的观测压缩策略继续执行，MUST NOT 因证据层故障中断工具调用循环或子任务执行，并 MUST 留下降级留痕。

原始观测全文 MUST 继续保存在既有的请求状态中；证据层 MUST NOT 引入新的外部存储依赖，MUST NOT 新增第三方服务。

#### Scenario: 证据管道异常时主流程继续

- **WHEN** 证据管道任一环节在处理某轮观测时抛出异常
- **THEN** 该轮发送视图 MUST 回退到既有压缩策略正常生成，Agent MUST 继续执行，且留痕中可查到降级记录与原因

### Requirement: 证据选择必须可观测

系统 MUST 为每轮证据处理留下记录，至少包含：轮次、新纳入单元数、判重数、低相关数、上板数、上板字符数、豁免原文数与豁免桩数、是否无新增证据；回取 MUST 记录编号、窗口、命中与否与返回字符数；plan 延迟恢复 MUST 记录子任务标识、请求编号、受理/拒绝编号与返回字符数。

当一轮观测未带来任何新的可用证据（全部判重或全部低于阈值，且无错误）时，系统 MUST 记录无新增证据状态，并在发送视图中提示模型：证据已足够则直接作答，否则更换关键词或工具；系统 MUST NOT 仅凭该状态自行终止或改写执行控制流。

#### Scenario: 连续重复检索可在记录中核查

- **WHEN** 连续两轮检索返回的内容全部与已有证据重复
- **THEN** 记录中 MUST 能查到两轮的判重数与无新增证据状态，且视图中 MUST 出现换关键词/工具或直接作答的提示

## Purpose

约束重规划的触发边界与输入完整性：何时允许触发、何时必须禁止、最多触发几次，以及送入重规划的内容必须携带什么、不得自相矛盾——使重规划退居为最后手段，而不是主要的纠偏机制。

## ADDED Requirements

### Requirement: 重规划只允许在方向性错误时触发

系统 MUST 仅在缺口性质属于**方向性错误**时触发重规划。

缺口性质 MUST 由上游以**结构化形式**给出，MUST NOT 依据自由文本推断。

构成方向性错误的唯一情形是：全部子任务结论均为**跑题**——即有内容返回，但没有任何一条涉及用户问题的核心实体、指标或时间。

理由：重规划的代价是"重新修订整轮计划 + 重跑"，而"某一步没取到数据"这类缺口属于执行期应当就地解决的问题。把两者混在同一个触发条件里，会让本该步级处理的问题付出整轮的代价。

#### Scenario: 全部结论跑题

- **WHEN** 汇总阶段判定全部子任务结论都答非所问（有内容但无一涉及问题的核心实体、指标或时间）
- **THEN** 系统 MUST 允许触发重规划

#### Scenario: 只是某一步没取到数据

- **WHEN** 缺口表现为"某个方向未取得有效数据"，而其余结论与问题相关
- **THEN** 系统 MUST NOT 触发重规划

#### Scenario: 缺口性质缺失或无法判定

- **WHEN** 上游未给出结构化的缺口性质，或给出的值不在允许集合内
- **THEN** 系统 MUST 按"非方向性错误"处理，MUST NOT 触发重规划

### Requirement: 重规划次数必须有硬性上限

同一轮请求内，重规划 MUST 至多发生一次。

达到上限后，即使仍判定证据不足，系统 MUST 转为诚实收尾，MUST NOT 再次触发重规划。

#### Scenario: 首次且唯一一次

- **WHEN** 本轮尚未发生过重规划，且缺口性质为方向性错误
- **THEN** 系统 MUST 允许触发一次重规划

#### Scenario: 已经重规划过一次

- **WHEN** 本轮已发生过重规划，之后汇总阶段仍判定证据不足
- **THEN** 系统 MUST NOT 再次触发重规划，MUST 以已有的部分答案诚实收尾

### Requirement: 触发重规划前必须排除非方向性缺口

即使证据不足判定成立，系统在下列任一情形下 MUST NOT 触发重规划：

- 缺口只是"未取得有效数据"（方向正确，只是数据源不可用）；
- 所有候选工具在本轮已被证明未取得有效数据（重规划只会重复已失效的路径）。

被排除时，系统 MUST 直接以已有信息给出诚实的部分答案，MUST NOT 编造内容补足。

#### Scenario: 候选工具已全部失效

- **WHEN** 本轮所有候选工具都已被证明未取得有效数据，且汇总判定证据不足
- **THEN** 系统 MUST NOT 触发重规划，MUST 以部分答案收尾

#### Scenario: 判定被排除

- **WHEN** 某次证据不足的判定因上述任一情形被排除出重规划
- **THEN** 系统 MUST 留下该次排除的可观测记录

### Requirement: 每条执行结果必须携带子任务归属

送给重规划的每条执行结果 MUST 携带其所属子任务标识。

理由：实测中每条结果的归属全部为空，重规划无法判断哪一步做完了、哪一步失败了，只能依据文本摘要猜测。

#### Scenario: 多条结果各自带归属

- **WHEN** 已有多次执行结果被送入重规划
- **THEN** 每条结果 MUST 携带其所属子任务标识，且与计划中的标识一致

#### Scenario: 归属不可得

- **WHEN** 某条结果确实无法关联到任何子任务
- **THEN** 系统 MUST 以显式标记表示"无归属"，MUST NOT 以空值留白

### Requirement: 已试过的数据源与查询必须结构化传递

重规划输入 MUST 包含本轮的取数尝试记录，至少覆盖：已试过的工具、已试过的位置或查询条件、该次尝试是否取得有效数据。

#### Scenario: 上次查找为空

- **WHEN** 上一轮曾在某个位置按某条件查找数据且结果为空
- **THEN** 重规划输入 MUST 包含该位置与该条件，并标明结果为空

#### Scenario: 取得有效数据的尝试

- **WHEN** 某次取数成功并取得有效数据
- **THEN** 该次尝试 MUST NOT 被标记为无效

### Requirement: 重规划输入不得包含已被自身记录否定的方向

当失败原因提出了某个方向，而同一份重规划输入已记录该方向曾被尝试且未取得有效数据时，系统 MUST NOT 原样传递该建议。

理由：实测第二次重规划的失败原因写着"建议检查 /data 目录下是否存在其他命名的销售数据文件"，而同一份输入的取数记录里已明确写着"在 /data 目录下未找到"。模型自由生成的建议与确定性事实直接矛盾且无人拦截，重规划于是又扫了一次 /data。

#### Scenario: 建议与记录矛盾

- **WHEN** 失败原因建议的方向已被同一份输入的记录证明未取得有效数据
- **THEN** 系统 MUST NOT 原样传递该建议，且 MUST 留下该矛盾被处理的记录

#### Scenario: 建议未与记录矛盾

- **WHEN** 失败原因建议的方向没有在先的失败记录
- **THEN** 该建议 MUST 正常传递

### Requirement: 工具失效判定必须依据是否取得有效数据

判定某个工具在本轮"已被证明无效"时，系统 MUST 依据该次调用是否取得有效数据，MUST NOT 仅依据其状态字段。

理由：实测中知识图谱检索未返回任何数据，但其状态被记为成功，于是逃过了失效工具去重，仍可能被新计划重新调用。

#### Scenario: 状态为成功但实际未取得数据

- **WHEN** 某次工具调用状态记为成功，但其返回内容表明检索失败、未取得任何业务数据
- **THEN** 该工具 MUST 被计入本轮已失效工具，并在重规划输入中被禁止重复调用

#### Scenario: 正常取得数据

- **WHEN** 某次工具调用取得有效数据
- **THEN** 该工具 MUST NOT 被计入已失效工具

# llm-call-budget Specification

## Purpose

让每次大模型调用的超时与重试预算可预测、可观测，并确保同一档位的模型在所有入口上使用同一套预算参数，避免"一次调用与它的重试共用一个预算"这种无法从配置推导的行为。

## Requirements

### Requirement: 超时预算按单次尝试独立计算

每次对模型提供方的调用尝试 MUST 获得独立的超时预算，取值来自该次调用所属档位的配置。一次尝试的超时或被取消 MUST NOT 消耗同一次调用中其他尝试的预算。

#### Scenario: 首次尝试超时后发生重试

- **WHEN** 某档位的单次预算为 T，且首次尝试在 T 内未返回
- **THEN** 该次尝试 MUST 在 T 时被判定为超时，且其后的重试 MUST 获得一个新的、完整的 T 预算

#### Scenario: 单次尝试在预算内成功

- **WHEN** 调用在 T 内正常返回
- **THEN** 系统 MUST 直接返回该结果，MUST NOT 触发重试

#### Scenario: 总耗时上限可推导

- **WHEN** 某档位配置了单次预算 T 与重试次数 N
- **THEN** 该候选的最坏总耗时 MUST 可由 T 与 N 推导得出，MUST NOT 出现无法解释的额外等待

### Requirement: 重试次数必须显式受控

同一档位内的重试次数 MUST 由系统配置显式给出，MUST NOT 依赖底层客户端库的隐式重试。

#### Scenario: 重试次数耗尽

- **WHEN** 某候选的首次尝试与全部重试均失败
- **THEN** 系统 MUST 保留每一次尝试的失败原因，并切换到下一个候选；若无其他候选，MUST 以包含最后一次失败原因的错误上抛

#### Scenario: 只发生一次瞬时故障

- **WHEN** 首次尝试因瞬时故障失败而随后一次尝试成功
- **THEN** 调用 MUST 成功返回，且首次尝试的失败原因 MUST 保留在日志中（MUST NOT 被静默吞掉）

### Requirement: 超时与失败必须可区分观测

日志 MUST 能区分"某一次尝试超时"与"重试之后仍然失败"，并 MUST 记录每次尝试的耗时。

#### Scenario: 排查一次超时

- **WHEN** 某次调用发生超时
- **THEN** 日志 MUST 包含所属档位、单次预算、尝试序号与该次尝试的实际耗时

#### Scenario: 排查超时耗尽后的整体失败

- **WHEN** 全部尝试结束后以失败告终
- **THEN** 日志 MUST 表明"已耗尽配置的尝试次数"，并给出每次尝试的失败类型

### Requirement: 同一档位的模型在所有入口使用同一套参数

同一档位的模型，无论由对话链路、编排链路还是知识图谱抽取链路调用，MUST 使用同一套超时、重试与思考开关参数。各入口 MUST NOT 各自硬编码这些参数。

#### Scenario: 知识图谱抽取链路

- **WHEN** 知识图谱抽取发起模型调用
- **THEN** 其单次超时 MUST 等于该模型所属档位配置的预算，MUST NOT 使用该组件自身的默认值

#### Scenario: 要求关闭思考

- **WHEN** 某次调用声明不使用思考
- **THEN** 所有入口 MUST 对该声明做同等处理：支持关闭的 provider MUST 收到关闭指令；不支持关闭的模型 MUST 跳过该指令且不因此报错

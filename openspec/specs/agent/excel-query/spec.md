# excel-query Specification

## Purpose

让表格读取工具在返回整表概览时就交付足够的"能怎么取数"的信息，使调用方在决定做聚合前不需要再额外读一次数据去看表长什么样，从而减少一次工具往返与其带来的上下文体积。

## Requirements

### Requirement: 概览必须披露可聚合能力

返回整表概览时，系统 MUST 为每张表分别给出「可用作分组依据的列」与「可参与数值聚合的列」。仅给出全部列名 MUST NOT 被视为满足本要求。

#### Scenario: 概览包含分组列与数值列

- **WHEN** 请求读取表格且未指定工作表
- **THEN** 每张表的输出 MUST 分别列出可用作分组的列与可聚合的数值列

#### Scenario: 某张表没有可用的分组列

- **WHEN** 某张表不存在可用作分组依据的列
- **THEN** 该表 MUST 明确说明"没有可用作分组的列"，MUST NOT 留空或省略该行

#### Scenario: 某张表没有可聚合的数值列

- **WHEN** 某张表不存在可参与数值聚合的列
- **THEN** 该表 MUST 明确说明这一点，且 MUST NOT 因此影响该表的其他信息渲染

### Requirement: 概览必须给出可直接复用的聚合参数

当某张表同时存在分组列与数值列时，概览 MUST 给出至少一组可直接照抄的聚合参数（工作表名、分组列、聚合列、聚合函数）。

#### Scenario: 单表可聚合

- **WHEN** 某张表同时具备分组列与数值列
- **THEN** 概览 MUST 给出至少一组可照抄的聚合参数

#### Scenario: 控制输出体积

- **WHEN** 某张表的数值列或分组列多于一个
- **THEN** 给出的示例参数 MUST 有数量上限，且 MUST NOT 为每张表穷举所有分组列与数值列的组合

### Requirement: 能力披露不得改变既有读取语义

新增的披露信息只作为附加说明。筛选、明细与聚合的返回内容与判定口径 MUST 保持不变。

#### Scenario: 既有聚合调用结果不变

- **WHEN** 调用方以既有参数（工作表 + 分组列 + 聚合列 + 聚合函数）请求聚合
- **THEN** 返回结果 MUST 与本次变更前一致

#### Scenario: 披露信息不参与实际取数

- **WHEN** 调用方忽略了披露的分组列或数值列建议、直接使用其他合法列名
- **THEN** 系统 MUST 照常按调用方给定的列执行，MUST NOT 以"不在建议列表里"为由拒绝

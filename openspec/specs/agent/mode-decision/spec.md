# mode-decision Specification

## Purpose

确保"用户是否明确给出了步骤"这一判定依据的是真实的步骤语义，而不是子串巧合——该判定会直接决定本轮走哪一种编排模式。

## Requirements

### Requirement: 显式步骤提示的判定不得基于子串巧合

判定用户是否明确给出了步骤时，系统 MUST 依据能够表达步骤语义的证据，MUST NOT 以单个字符的子串命中作为依据。依据不足以确认时，系统 MUST NOT 以"规则硬命中"级别的高置信度呈现该判定。

理由：实测中正则 `先|步骤|第N步|数字、` 让「优先做哪些行业」命中（匹配片段只有「先」），于是被判定为"用户明确说出了显式步骤"并以高置信度强制进入计划模式。任何含「优先」「首先」的中文请求都会走到这条路径。

#### Scenario: 步骤相关字符只出现在词语内部

- **WHEN** 用户问题中的步骤相关字符仅出现在某个词的内部（例如「优先」中的「先」）
- **THEN** 系统 MUST NOT 将其判定为显式步骤提示

#### Scenario: 出现完整步骤表述

- **WHEN** 用户问题中出现「先…再…最后…」或「步骤 1」「第 2 步」这类完整步骤表述
- **THEN** 系统 MUST 判定为显式步骤提示

### Requirement: 步骤提示的内容必须是步骤语义而非整句问题

判定为显式步骤提示时，系统 MUST 只保留其中表达步骤语义的部分，MUST NOT 把整句问题原样作为步骤提示。

理由：实测中命中后返回的是整句问题（截到 120 字），该字符串随后被当作"宏观计划参考"注入规划器，与用户问题逐字重复，既不携带新信息，又让规划器把"复述问题"当成一条计划依据。

#### Scenario: 命中内容不含步骤语义

- **WHEN** 命中的内容在去除步骤标记后不再表达任何步骤语义
- **THEN** 系统 MUST 视为未命中，MUST NOT 输出步骤提示

#### Scenario: 命中内容确实表达步骤顺序

- **WHEN** 命中的内容确实表达了步骤顺序
- **THEN** 输出的步骤提示 MUST 只包含该步骤表述，MUST NOT 包含与步骤无关的问题原文

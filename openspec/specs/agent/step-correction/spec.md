# step-correction Specification

## Purpose

让执行期在"这一步没拿到想要的东西"时，能够在系统给出的**封闭候选方向**里选一个继续，而不是自行发明方向，也不必等到整轮重规划。

## Requirements

### Requirement: 系统必须为执行期提供封闭的候选方向列表

系统 MUST 在子任务执行前，由代码**确定性**组装一个候选方向列表，MUST NOT 由模型生成该列表。

候选 MUST 来自以下两个差集：

1. 已提取的结构化事实（数据资产及其位置）**减去**本轮已尝试过的路径；
2. 当前工具白名单**减去**本轮已调用过的工具。

候选 MUST 与当前工具白名单求交：若白名单中不存在能消费该候选的工具，则该候选 MUST NOT 进入列表。

本轮已尝试且未取得有效数据的路径 MUST NOT 进入列表。

每条候选 MUST 带一个短标识与一句话描述；列表总长度 MUST 受上限约束（约 300 字符）。

理由：本 trace 中模型在没有候选集时被要求给出纠偏方向，结果是盲扫 `/data`——一个已被同一份输入记录证否的路径。有了候选集，"与自身记录矛盾"这个问题在构造阶段就被结构性排除，而不是事后靠拦截。

#### Scenario: 存在可用的替代资产

- **WHEN** 已提取出数据资产，且其中部分在本轮未被尝试
- **THEN** 这些未尝试的资产 MUST 出现在候选列表中，且其位置与文档中逐字一致

#### Scenario: 已证否的路径被剔除

- **WHEN** 某个路径在本轮已尝试且未取得有效数据
- **THEN** 该路径 MUST NOT 出现在候选列表中

#### Scenario: 白名单不含能消费该资产的工具

- **WHEN** 某个已提取资产需要当前白名单之外的工具才能读取
- **THEN** 该资产 MUST NOT 出现在候选列表中，且系统 MUST 记录一条告警

#### Scenario: 候选为空

- **WHEN** 两个差集与白名单求交后为空
- **THEN** 系统 MUST NOT 注入候选列表，且 MUST NOT 因缺少候选而中断本轮请求

### Requirement: 候选方向列表只在需要时注入

系统 MUST 仅在下列任一条件成立时注入候选列表：

1. 本步的工具调用未取得有效数据（错误或空数据，确定性判据）；
2. 上一步的自评为「未解决」或「部分解决」。

正常成功、且上一步自评为已解决的子任务 MUST NOT 注入该列表。

理由：常驻注入会让模型分不清"我现在应该换方向"与"我只是需要知道有哪些工具"；且候选集依赖执行期状态（已试路径、已用工具），每次重算没有必要。

#### Scenario: 本步取数失败

- **WHEN** 本步工具调用返回错误或空数据
- **THEN** 下一步的提示词中 MUST 出现候选方向列表

#### Scenario: 上一步自评为未解决

- **WHEN** 上一步虽然执行成功，但自评为「未解决」或「部分解决」
- **THEN** 本步的提示词中 MUST 出现候选方向列表

#### Scenario: 一切正常

- **WHEN** 上一步自评为已解决，且本步工具调用取得有效数据
- **THEN** 提示词中 MUST NOT 出现候选方向列表

### Requirement: 模型只能从候选列表里选择，不得自行构造

模型 MUST 只输出所选候选项的标识，或明确表示不选。模型 MUST NOT 在纠偏指令中自行构造工具名、参数或路径。

系统 MUST 负责把选中的标识翻译为具体动作，并 MUST 在应用前对该动作做一次白名单校验。

标识不在本次注入的候选列表中，或纠偏指令无法解析时，系统 MUST 忽略该指令并按既有口径降级为「继续执行下一个子任务」，MUST NOT 因此丢弃本步已产出的结论。

理由：模型没有信息基础来发明方向（本 trace 已证明），但完全有基础在有限选项里做语义匹配。前者需要它发明，后者只需要它判断。

#### Scenario: 选中一项候选

- **WHEN** 模型输出了本次候选列表中的某个标识
- **THEN** 系统 MUST 把该标识翻译为具体动作并应用到计划

#### Scenario: 明确不选

- **WHEN** 模型未输出任何候选项标识
- **THEN** 系统 MUST 按既有流程继续执行下一个子任务

#### Scenario: 标识不在列表中

- **WHEN** 模型输出的标识不属于本次注入的候选列表
- **THEN** 系统 MUST 忽略该指令并降级为继续执行，MUST NOT 因该指令而失败

#### Scenario: 解析失败不影响本步结论

- **WHEN** 模型返回了有效的子任务结论但纠偏指令无法解析
- **THEN** 系统 MUST 保留该结论，并按「继续执行下一个子任务」推进

### Requirement: 证据缺口检测必须是确定性的，且不得新增模型调用

系统 MUST 提供一次确定性的证据缺口检测：比对**两个数据集**——

- **数据集 A（问题侧核心词）**：从系统已有的结构化文本中抽取并分词得到的集合。可取来源按优先级为：本轮目标、子问题、意图树命中路径、已提取的结构化事实；均缺失时回退到改写后的问题文本。
- **数据集 B（本步返回内容）**：本步工具调用返回的原始文本。

判据为 A 中的词在 B 中的**字面出现率**；低于阈值时置位证据缺口信号。该信号 MUST 可作为开放纠偏通道的补充触发条件。

比对 MUST 只针对**本步**的返回内容，MUST NOT 掺入历史结论——否则历史结论会抬高覆盖率，导致"本步返回跑题"被漏检。

系统 MUST NOT 为此新增模型调用，MUST NOT 引入向量化检索。分词 MUST 使用本地库（零外部调用）。

**数据集 A 为空时 MUST NOT 置位**；**数据集 B 为空时 MUST NOT 置位**（纯推理步骤无返回内容，覆盖率无意义）。宁可漏触发，不得误伤正常步骤。

理由：本 trace 的典型失败不是"没取到数据"，而是"取到了数据但数据不对"（返回销售记录，问题问行业优先级）。仅以"取数失败"为触发条件覆盖不到这种情形。

#### Scenario: 返回内容与问题核心词不匹配

- **WHEN** 本步返回内容中，问题核心词的覆盖率低于阈值
- **THEN** 系统 MUST 置位证据缺口信号，并据此开放纠偏通道

#### Scenario: 返回内容覆盖正常

- **WHEN** 本步返回内容中，问题核心词的覆盖率达到阈值
- **THEN** 系统 MUST NOT 因证据缺口而开放纠偏通道

#### Scenario: 核心词集合为空

- **WHEN** 未能从已有结构化文本中得到任何核心词
- **THEN** 系统 MUST NOT 置位证据缺口信号

#### Scenario: 本步无返回内容

- **WHEN** 本步为纯推理子任务，或工具未返回任何文本
- **THEN** 系统 MUST NOT 置位证据缺口信号

### Requirement: 就地纠偏必须受配额约束，且只在 cursor 之后插入新计划项

系统 MUST 限制单轮请求内的就地纠偏次数（不超过剩余调用预算的一半），配额耗尽即关闭该能力。

应用纠偏时，系统 MUST 在当前 cursor 的下一个位置**插入**一条新的 tool 子任务（不替换、不删除任何已有计划项）；当前步与已有计划项 MUST 保持原样，cursor MUST 保持不变，已跳过的子任务记录与提前收尾标记 MUST NOT 被清空。新插入项的 id MUST 在计划内唯一。

理由：执行期原本"只能收缩"的约束是为了防止计划无界膨胀。插入式纠偏放开了"新增一步"，但膨胀边界由配额硬性兜住（未设总预算时上限 2 次），且只允许在 cursor 之后追加、插入步下一步立即执行，不得改动既有计划。

#### Scenario: 配额内生效

- **WHEN** 触发了纠偏条件且剩余配额大于零
- **THEN** 系统 MUST 应用该次纠偏并扣减配额

#### Scenario: 配额耗尽

- **WHEN** 触发了纠偏条件但剩余配额为零
- **THEN** 系统 MUST 忽略该次纠偏指令并降级为继续执行

#### Scenario: 应用纠偏不重置执行进度

- **WHEN** 一次纠偏被应用到计划
- **THEN** cursor MUST 保持不变，已跳过记录与提前收尾标记 MUST 保持原样

### Requirement: 就地纠偏必须留痕

每次就地纠偏 MUST 留下可观测记录，至少包含：触发条件（取数失败 / 上一步未解决 / 证据缺口）、模型选中的候选项标识、应用后的目标动作、剩余配额。

候选集为空时 MUST 记录一条告警，至少包含：被白名单排除的资产名称与原因。

#### Scenario: 纠偏被记录

- **WHEN** 一次就地纠偏被应用
- **THEN** 该次运行的记录中 MUST 能查到候选项标识、目标动作与剩余配额

#### Scenario: 候选集为空被记录

- **WHEN** 存在已提取的事实，但候选集与白名单求交后为空
- **THEN** 记录中 MUST 能查到被排除的资产名称与排除原因

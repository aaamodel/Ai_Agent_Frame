# plan-execute-control Specification

## Purpose

让 plan_execute 模式在执行期对模型可见、可收缩：每一步都能看到计划全貌与成败状态，并允许跳过冗余子任务或在证据充分时提前收尾，从而避免为凑齐计划而执行不必要的工具调用与总结。

## Requirements

### Requirement: 每个子任务执行前必须向模型呈现计划台账

系统 MUST 在每次执行子任务前，向模型呈现计划台账，其中每一行至少包含：子任务标识、该子任务要解决的问题、所调用的工具（推理型子任务须标明无工具）、以及当前状态。状态 MUST 至少区分「已完成 / 正在执行 / 待执行 / 已跳过 / 失败」。

台账 MUST 由计划本身与已执行记录推导得出，系统 MUST NOT 维护一份可能与之漂移的独立状态副本。

#### Scenario: 执行中段可见计划全貌

- **WHEN** 计划含 4 个子任务且正在执行第 3 个
- **THEN** 模型 MUST 能同时看到第 1、2 个的完成状态、第 3 个的进行状态，以及第 4 个的待执行状态

#### Scenario: 失败步骤在台账中标为失败

- **WHEN** 某个子任务因工具错误或空数据未取得有效结果
- **THEN** 该子任务在台账中 MUST 显示为失败状态，而不仅是呈现一段结论文本

### Requirement: 台账必须标注子问题是否被真正解决

系统 MUST 在台账中为已执行的子任务额外标注「是否解决了它要解决的问题」，至少区分「是 / 部分 / 否」，且 MUST 与执行状态**分列呈现**——执行状态是客观的调用结果，是否解决是语义判断，两者不等价。

该标注 MUST 按来源区分：

- 执行失败的子任务（工具错误、空数据、预算熔断、审批拒绝）：系统 MUST 直接标记为「否」，MUST NOT 依赖模型判断——这些步骤未经过结论提炼，模型并未看到数据。
- 正常执行并完成结论提炼的子任务：该标注 MUST 由模型在同一次调用中自评得出。
- 系统 MUST NOT 为获取该标注而额外发起一次模型调用。

#### Scenario: 工具成功但未答到点上

- **WHEN** 某子任务工具调用成功，但返回内容未包含该子问题所需的信息
- **THEN** 该子任务的执行状态为成功，而「是否解决」MUST 为「否」或「部分」

#### Scenario: 工具失败时强制标记为否

- **WHEN** 某子任务因工具错误或空数据未取得有效结果
- **THEN** 系统 MUST 将其「是否解决」直接标记为「否」，且 MUST NOT 采用模型自评

### Requirement: 模型可跳过后续子任务

模型 MUST 能够指定跳过一个或多个尚未执行的子任务。被跳过的子任务 MUST NOT 被执行，且 MUST 在台账中标记为已跳过。跳过 MUST NOT 影响任何已执行步骤的结果。

#### Scenario: 后续子任务的答案已由前序步骤取得

- **WHEN** 模型判定某个待执行子任务要取的答案已在前序子任务的结论中
- **THEN** 系统 MUST 跳过该子任务，并直接推进到下一个未被跳过的子任务

#### Scenario: 跳过后跨过多个任务

- **WHEN** 模型指定跳过第 3、4 个子任务
- **THEN** 系统 MUST 从当前位置直接推进到第 5 个子任务，且第 3、4 个 MUST NOT 被执行

### Requirement: 模型可在证据充分时提前收尾

模型 MUST 能够在判定已取得充分证据时提前结束剩余全部子任务。系统 MUST 随即转入汇总阶段，并 MUST NOT 执行剩余子任务。

提前收尾 MUST NOT 绕过证据充分性判定：系统 MUST 仍将已有结论交由汇总阶段判定，判定不足时仍 MUST 可按既有机制补取证据。

#### Scenario: 中途判定答案已足够

- **WHEN** 计划尚有 3 个未执行子任务，而模型判定已有结论足以回答用户问题
- **THEN** 系统 MUST 跳过全部剩余子任务并进入汇总阶段

#### Scenario: 提前收尾后证据不足仍可补取

- **WHEN** 提前收尾后汇总阶段判定证据不足以回答问题
- **THEN** 系统 MUST 仍可触发重规划补取证据，且 MUST NOT 直接产出空答案

### Requirement: 控制指令与子任务结论在同一次模型调用中产出

控制指令（继续 / 跳过 / 提前收尾）MUST 与子任务结论在同一次模型调用中一并产出，系统 MUST NOT 为此额外发起一次模型调用。

控制指令解析失败时，系统 MUST 降级为「继续执行下一个子任务」，MUST NOT 因子任务结论本身有效而丢弃它。

#### Scenario: 解析失败不影响本步结论

- **WHEN** 模型返回了有效的子任务结论但控制指令无法解析
- **THEN** 系统 MUST 保留该结论，并按「继续执行下一子任务」推进

### Requirement: 不提供新增或修改子任务的能力

本能力 MUST 仅提供「跳过」与「提前收尾」两种收缩操作。系统 MUST NOT 提供新增子任务或修改既有子任务内容的能力。

#### Scenario: 模型尝试新增子任务

- **WHEN** 模型在控制指令中声明了新增子任务或修改既有子任务
- **THEN** 系统 MUST 忽略该部分指令，仅处理跳过与提前收尾，并记录一条忽略原因的留痕

### Requirement: 收缩行为必须留痕

每次跳过或提前收尾 MUST 留下可观测记录，至少包含：被跳过或提前结束的子任务标识、模型给出的理由。

#### Scenario: 跳过被记录

- **WHEN** 模型跳过某个子任务并给出理由
- **THEN** 该次运行的记录中 MUST 能查到被跳过的子任务标识与理由

# agent-goal Specification

## Purpose

为本轮 agent 运行提供一个简明、稳定的目标锚点：由改写阶段产出、随状态传递、在每个决策点以同一份内容注入，使「跳过子任务」与「提前收尾」这类收缩决策有可依据的判断基础。

## Requirements

### Requirement: 改写阶段必须产出本轮目标

系统 MUST 在问题改写阶段产出 `agent_goal`：一句话说明本轮要达成的最终目标（用户最终想要得到的交付物或结论）。该字段 MUST NOT 是对原始问题的复述或改写后问题的副本。

产出该字段 MUST 复用既有的改写调用，MUST NOT 为此额外发起一次模型调用。

#### Scenario: 复杂请求产出交付物形态的目标

- **WHEN** 用户要求「帮我做一份 2026 年 8 月的销售复盘，重点看赢单率和输单原因」
- **THEN** `agent_goal` MUST 描述最终交付物（例如「输出 8 月销售复盘，含赢单率与输单原因结论」），而不是复述用户原句

#### Scenario: 简单问候不产出空目标

- **WHEN** 用户只说「你好」这类无需取数的请求
- **THEN** `agent_goal` MUST 仍有可读值（例如「回应用户问候」），MUST NOT 为空字符串

### Requirement: 目标必须随状态传递到所有决策点

`agent_goal` MUST 随意图阶段的产物流入图状态，且 MUST 能被任意节点读取。系统 MUST NOT 为该字段维护与状态平行的第二份副本。

#### Scenario: 运行期可读取目标

- **WHEN** 一次运行进入执行阶段
- **THEN** 执行节点 MUST 能从状态中取得本轮 `agent_goal`，且其值与改写阶段产出一致

### Requirement: 每个依赖目标的决策点必须注入同一份目标

系统 MUST 在同一份目标下运行整轮请求，并在以下三个决策点注入它：

1. ReAct 模式的系统提示段（Function Calling 与文本两种协议）；
2. 计划模式的规划提示词；
3. 子任务执行前的提示词（与计划台账一起）。

三处 MUST 注入相同内容，MUST NOT 出现某一处使用改写后问题、另一处使用目标的不一致。

#### Scenario: ReAct 模式持有目标

- **WHEN** 请求判定为 ReAct 模式并进入首轮
- **THEN** 系统提示段中 MUST 包含本轮 `agent_goal`

#### Scenario: 计划模式持有目标

- **WHEN** 请求判定为计划模式并生成子任务
- **THEN** 规划提示词中 MUST 包含本轮 `agent_goal`

#### Scenario: 子任务执行时持有目标

- **WHEN** 某个子任务执行前的提示词被组装
- **THEN** 该提示词中 MUST 包含本轮 `agent_goal`

### Requirement: 目标在计划台账中以首行呈现而非表格列

当台账与目标一并注入时，目标 MUST 作为台账块的**首行**呈现，MUST NOT 作为表格中的一列。

理由：目标不是某个子任务的属性，而是全部子任务共同的约束；作为列会让每一行重复同一段文字。

#### Scenario: 台账块首行是目标

- **WHEN** 渲染给模型的计划台账被组装
- **THEN** 目标 MUST 出现在表格上方的独立行中，且表格内 MUST NOT 为每个子任务重复该文字

### Requirement: 目标缺失时必须回退且不得阻断链路

改写未产出该字段、或产出为空时，系统 MUST 回退为「改写后的问题」（必要时截断），并 MUST 继续执行，MUST NOT 因缺少目标而中断本轮请求或抛出异常。

#### Scenario: 模型漏输出目标字段

- **WHEN** 改写输出不含 `agent_goal`
- **THEN** 系统 MUST 使用改写后的问题作为目标，且 MUST 完成本轮请求

### Requirement: 目标长度必须受约束

`agent_goal` MUST 受长度上限约束，以保证它在每一次调用中注入都不会显著抬高输入体积。

#### Scenario: 模型输出过长目标

- **WHEN** 模型产出的目标超过长度上限
- **THEN** 系统 MUST 将其截断到上限后再注入，MUST NOT 原样注入超长文本

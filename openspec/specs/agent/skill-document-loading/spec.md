# skill-document-loading Specification

## Purpose

让技能文档里的结构化事实（数据资产所在位置等）在读取后直接进入运行状态并被后续环节复用，而不是只存在于一次模型自由摘要里。

## Requirements

### Requirement: 技能文档的结构化事实必须提取进运行状态

读取技能文档后，系统 MUST 从中提取结构化事实并写入运行状态。提取范围 MUST 至少覆盖文档声明的数据资产名称及其所在位置。

这些事实 MUST NOT 仅由模型生成的摘要承担传递职责。

理由：实测中约 4,830 字符的技能文档被整篇交给子任务模型做自由摘要，摘要产出约 180 字，把文档里逐字写明的资产位置全部丢弃；后续重规划因此连续两次盲扫目录，全部为空。

#### Scenario: 文档含资产位置表

- **WHEN** 技能文档中包含声明数据资产及其位置的表格
- **THEN** 运行状态中 MUST 出现这些资产的名称与位置，且与文档中逐字一致

#### Scenario: 文档不含该结构

- **WHEN** 技能文档中不存在可识别的资产位置结构
- **THEN** 系统 MUST 回退为既有行为并继续执行，MUST NOT 中断本轮请求

#### Scenario: 提取结果为空

- **WHEN** 提取过程未得到任何事实
- **THEN** 系统 MUST NOT 向后续环节注入空事实集合，且 MUST 继续执行

### Requirement: 结构化事实必须传递到后续环节

已提取的事实 MUST 在子任务执行与重规划时可见。

#### Scenario: 重规划时可见

- **WHEN** 本轮进入重规划
- **THEN** 重规划输入中 MUST 包含已提取的资产位置

#### Scenario: 后续子任务可见

- **WHEN** 后续子任务需要按位置读取数据资产
- **THEN** 该子任务的输入中 MUST 能取到已提取的位置

### Requirement: 事实冲突时以提取结果为准

当模型生成的摘要与已提取的结构化事实不一致时，系统 MUST 以提取出的事实为准。

#### Scenario: 摘要遗漏了某个资产位置

- **WHEN** 摘要中未提及某个已在文档中声明的资产位置
- **THEN** 该位置 MUST 仍然对后续环节可见

#### Scenario: 摘要给出了文档中不存在的资产位置

- **WHEN** 摘要中出现文档中并不存在的资产位置
- **THEN** 系统 MUST NOT 将其作为已提取事实传递

# excel-tool-retirement Specification

## Purpose

Excel 取数工具退役后，系统在任何位置都不得再暴露或引用它们——工具注册、意图树、
技能允许工具清单、提示词、危险工具名单、评测 schema 与测试必须同步清理，取数路径一律
指向 SQL 工具，不留悬空引用。

## Requirements

### Requirement: 已退役的 Excel 工具不得再被暴露或引用

已退役的 Excel 取数工具（读取、查询、写入三个）MUST NOT 出现在下列任何位置：

- 工具注册表与工具清单；
- 意图树的工具绑定与路由文案；
- 技能的允许工具清单与数据资产地图；
- 执行期 / 规划期提示词；
- 危险工具审批名单；
- 评测集的工具 schema 与断言；
- 自动化测试。

理由：这些工具当前被约 30 个文件引用。只删实现而不清引用，会留下指向不存在工具的
路由规则与提示词——模型被引导去调用一个已被删除的工具，比保留旧工具更糟。

#### Scenario: 工具清单中无已退役工具

- **WHEN** 枚举当前可用工具
- **THEN** MUST NOT 出现任何已退役的 Excel 取数工具

#### Scenario: 全仓无悬空引用

- **WHEN** 在代码、技能文档、评测集与测试中搜索已退役工具的名称
- **THEN** MUST 无匹配（历史归档记录除外）

#### Scenario: 危险工具名单同步清理

- **WHEN** 检查危险工具审批名单
- **THEN** MUST NOT 包含已退役的 Excel 工具

### Requirement: 取数类问题必须路由到 SQL 工具

针对业务数据的取数、统计、排名、占比、同环比等问题，系统 MUST 将其路由到 SQL 工具，
MUST NOT 引导模型使用按文件路径取数的方式。

#### Scenario: 取数问题指向 SQL 工具

- **WHEN** 用户提出需要查询或统计业务数据的问题
- **THEN** 可用的工具与路由提示 MUST 指向 SQL 工具

#### Scenario: 不再出现"按路径取数"的引导

- **WHEN** 检查规划期与执行期的取数引导文案
- **THEN** MUST NOT 出现要求模型构造文件路径 / 工作表名 / 过滤列组合的指引

### Requirement: 写操作判定必须改用 SQL 写工具

系统判断"某子任务是否为写操作"时 MUST 依据 SQL 写工具，MUST NOT 再依据已退役的
Excel 写工具。

理由：写操作判定错误会导致"写失败被当成成功"——这是既有 trace 里出现过的事故，
判定名单必须与当前工具集严格同源。

#### Scenario: 写操作判定覆盖 SQL 写工具

- **WHEN** 一个子任务调用了 SQL 写工具
- **THEN** 系统 MUST 将其识别为写操作

#### Scenario: 失败重试提示不含退役工具

- **WHEN** 写操作失败需要重试
- **THEN** 重试提示 MUST 只提及当前存在的写工具与参数形态

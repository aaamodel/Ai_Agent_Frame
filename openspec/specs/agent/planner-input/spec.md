# planner-input Specification

## Purpose

约束前置阶段向规划器注入的参考块：只有确实携带规划器无法自行推导的信息时才注入，并且不得出现与已注入内容逐字重复的整段。

## Requirements

### Requirement: 与用户问题逐字相同的参考段必须整段不注入

当"冷启动参考段"去除首尾空白与内部换行后的全部内容，与用户问题（或改写后的问题）逐字相同时，系统 MUST NOT 注入该段。

理由：该段存在的意义是提供规划器无法自行推导的步骤语义。内容等于用户原问题时，它既不携带新信息，又会让"复述问题"看起来像一条计划依据。

#### Scenario: 参考段退化为问题复述

- **WHEN** 参考段的内容与用户问题（或改写后的问题）逐字相同
- **THEN** 规划器提示词中 MUST NOT 出现该参考段

#### Scenario: 参考段携带真实步骤语义

- **WHEN** 参考段的内容与用户问题不同（例如给出了「先取数、再对账、最后出结论」）
- **THEN** 该参考段 MUST 正常注入

#### Scenario: 两侧均为空

- **WHEN** 参考段为空或不存在
- **THEN** 系统 MUST NOT 注入该段，也 MUST NOT 注入其标题占位

### Requirement: 意图标签必须达到置信度门槛才可作为约束注入

注入意图标签时，系统 MUST 附带该标签的置信度。置信度低于配置门槛时，系统 MUST NOT 将该标签作为拆解方向约束注入规划器。

理由：规划器会把注入的意图当作硬约束去分配工具，错误意图比没有意图更糟。实测中一个不该注入的意图标签（问题问的是行业优先级策略，标签却是"实体关系图谱"）使规划器把子任务分配给了知识图谱检索，白跑一次工具调用与一次子任务提炼。

#### Scenario: 置信度不足

- **WHEN** 意图聚合给出的置信度低于配置门槛
- **THEN** 规划器提示词中 MUST NOT 出现要求围绕该意图方向拆解的约束块

#### Scenario: 置信度达标

- **WHEN** 置信度达到或超过配置门槛
- **THEN** 该意图标签 MUST 被注入，并 MUST 附带其置信度

#### Scenario: 置信度缺失或非法

- **WHEN** 上游未提供置信度，或提供了无法解析的值
- **THEN** 系统 MUST 按"置信度不足"处理，MUST NOT 默认视为达标

### Requirement: 规划器侧只注入技能清单

规划器 MUST 只接收技能清单（技能名、一句话描述、触发条件、源文件位置）。读取技能文件、遵守其工作流这类执行期指引 MUST NOT 注入规划器。

理由：规划只需知道"有哪些技能可用"；读取与遵守发生在执行期。同一份执行指引同时出现在规划器与执行器提示词中，等于让渐进式披露被两个环节各承担一次。

#### Scenario: 存在可用技能

- **WHEN** 技能树中存在至少一个可用技能
- **THEN** 规划器提示词 MUST 包含该技能的清单条目，且 MUST NOT 包含"如何读取技能文件"的操作步骤说明

#### Scenario: 无可用技能

- **WHEN** 技能树为空
- **THEN** 系统 MUST NOT 注入技能清单段，也 MUST NOT 留下其空标题

#### Scenario: 清单标题必须紧邻清单内容

- **WHEN** 技能清单段被注入
- **THEN** 该段的标题 MUST 紧邻技能清单内容本身，MUST NOT 被其他注入块的标题插入其间

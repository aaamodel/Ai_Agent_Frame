# kb-collection-routing Specification

## Purpose

让"这次检索打给哪些知识库集合"从一个**自由文本参数**变成**受约束的枚举选择**：集合名只能取自系统真实持有的集合清单，清单之外的名字在进入检索前就被拦下，且每个可选集合都随参数附带一句说明，使模型具备"选得对"所必需的信息基础。

## Requirements

### Requirement: 集合参数的取值必须来自系统真实持有的集合清单

向模型暴露的知识库检索工具，其集合参数 MUST 以**枚举**形式声明可取值，MUST NOT 是一个无约束的自由字符串数组。

枚举的取值 MUST 恒等于**当前注册表中具备非空描述的集合名全集**：

- 注册表中存在但描述为空的集合 MUST NOT 进入枚举——没有描述的集合无法被判定适用场景，把它放进候选只会诱导误选；
- 枚举 MUST 随注册表在运行时刷新（新增/删除集合后，**下一次**请求即可选到或不再可选），MUST NOT 被固化在进程启动时刻；
- 集合名之外的取值 MUST NOT 出现在枚举中。

理由：一次实测中 Planner 为检索工具传入了 `product_docs` / `sales_policies` / `pricing_guide` 三个**并不存在**的集合名——真实集合清单里没有这三个名字。两个子任务因此全部空召回，工具被连续无效计数硬熔断，整轮降级收尾。参数空间无约束时，"编一个看起来合理的名字"与"从真实清单里选"对模型而言毫无区别。

#### Scenario: 枚举等于具备描述的集合全集

- **WHEN** 注册表中存在 N 个具备非空描述的集合
- **THEN** 集合参数的枚举 MUST 恰好包含这 N 个集合名

#### Scenario: 无描述的集合不进入枚举

- **WHEN** 注册表中某个集合的描述为空
- **THEN** 该集合名 MUST NOT 出现在枚举中

#### Scenario: 集合清单在运行时变化后即刻生效

- **WHEN** 运行期间注册表新增或删除了一个具备描述的集合
- **THEN** 下一次构造工具参数时，枚举 MUST 反映变化后的清单，无需重启进程

#### Scenario: 工具参数不得给出不存在的示例集合名

- **WHEN** 渲染集合参数的说明文本
- **THEN** MUST NOT 出现任何不在注册表中的集合名作为示例

### Requirement: 每个可选集合必须随参数附带一句描述

集合参数的说明 MUST 为**每一个**枚举取值给出一句语义描述，使模型能在同一处看到"有哪些集合"与"各是什么"。

描述 MUST 来自集合自身的元数据，MUST NOT 由调用方另行拼接猜测。

理由：仅有枚举只能让模型"不能编"，不能让它"选得对"。实测中模型在连"有哪些集合"都不知道的情况下生成了名字；反过来，只给名字不给语义，模型只能在真实集合里盲选。

#### Scenario: 每个枚举值都有对应描述

- **WHEN** 枚举包含 N 个集合名
- **THEN** 参数说明中 MUST 逐条列出这 N 个集合名及各自的描述

#### Scenario: 描述缺失时不出现空条目

- **WHEN** 某个集合因描述为空而未进入枚举
- **THEN** 参数说明中 MUST NOT 出现该集合名，也 MUST NOT 留下无描述的空条目

### Requirement: 枚举之外的取值必须被静默过滤，且不得导致请求失败

当调用方仍传入了不在当前注册表内的集合名时，系统 MUST 在进入检索前将其过滤掉。

- 若过滤后仍有合法集合名，检索 MUST 仅在这些合法集合内进行；
- 若过滤后为空，系统 MUST 回落为**不限定集合**的检索，MUST NOT 因此使请求失败或返回错误；
- 过滤与回落 MUST 留下可观测记录，至少包含被丢弃的取值与是否发生回落。

以静默过滤而非拒绝的理由：枚举强制力取决于模型与网关是否支持严格 schema；一次幻觉不应让整轮请求失败，"还能检索到东西"优先于"严厉报错"。

#### Scenario: 部分合法部分越界

- **WHEN** 传入的集合名中既有合法值也有越界值
- **THEN** 检索 MUST 仅使用合法值限定范围，越界值被丢弃

#### Scenario: 全部越界

- **WHEN** 传入的集合名全部不在注册表内
- **THEN** 系统 MUST 回落为不限定集合的检索，且请求 MUST 正常完成

#### Scenario: 越界回落被记录

- **WHEN** 发生了一次越界过滤或回落
- **THEN** 该次运行的记录中 MUST 能查到被丢弃的取值

### Requirement: 集合参数约束不得依赖意图层的集合定向

集合参数的枚举与描述 MUST 独立于"意图识别是否解析出某个知识库集合节点"而生效。

当意图层未能解析出知识库集合节点、因而未注入任何集合定向约束时，工具参数上的枚举与描述 MUST 依然完整存在。

理由：原设计的约束链是"意图层命中集合节点 → 注入硬约束文本 → 模型照办"。实测中该次调用意图层未解析出集合节点，硬约束文本从未注入，模型中处于**无任何集合信息**的状态——漏洞不在于约束文本没写好，而在于没有兜底层。

#### Scenario: 意图层未命中集合节点时仍有枚举

- **WHEN** 意图层未解析出知识库集合节点
- **THEN** 工具参数上的集合枚举与描述 MUST 仍然完整可用

#### Scenario: 意图层命中集合节点时不冲突

- **WHEN** 意图层已解析出集合节点并注入定向约束
- **THEN** 该定向约束所指向的集合 MUST 属于枚举取值之内
